Astro makes working with external data incredibly easy and efficient. Because Astro components run on the server at build time (or request time in SSR mode), you can securely fetch data from any API, database, or Headless CMS directly in your component's frontmatter.

In this lesson, we will explore how to fetch data, handle asynchronous operations, and render external content.

## The Global `fetch()` Function

Astro provides access to the global `fetch()` function in the frontmatter of all your components. This works exactly like the browser `fetch` API, but it runs securely on the backend.

### Basic Data Fetching

To fetch data, you simply use top-level `await` inside the component script (the area between `---`).

```astro
---
// Example: src/pages/users.astro
const response = await fetch('https://jsonplaceholder.typicode.com/users');
const users = await response.json();
---

<h1>User Directory</h1>
<ul>
  {users.map((user) => (
    <li>
      <strong>{user.name}</strong> ({user.email})
    </li>
  ))}
</ul>
```

When Astro builds your site, it will make the HTTP request, wait for the response, generate the HTML with the data, and send *only the HTML* to the browser. The JavaScript used to fetch the data is stripped away completely.

## Secure API Keys

Because the frontmatter code never reaches the browser, you can safely use secret API keys, database passwords, and environment variables without exposing them to the client.

To use environment variables, create a `.env` file in the root of your project:

```env
# .env
SECRET_API_KEY=my-super-secret-key
```

Then, you can access it in your `.astro` files using `import.meta.env`:

```astro
---
const apiKey = import.meta.env.SECRET_API_KEY;

const response = await fetch('https://api.mycms.com/posts', {
  headers: {
    'Authorization': `Bearer ${apiKey}`
  }
});
const data = await response.json();
---
```

<Alert type="warning">
Never prefix secret variables with `PUBLIC_` (e.g., `PUBLIC_API_KEY`), as Astro will expose those to the client-side JavaScript. Keep server-only variables without the `PUBLIC_` prefix!
</Alert>

## Fetching Data for Dynamic Routes

If you are using dynamic routes (like `[id].astro`) and SSG (Static Site Generation), you need to fetch your data inside the `getStaticPaths()` function.

`getStaticPaths` must return an array of objects, where each object contains a `params` key to define the route, and an optional `props` key to pass data to the page.

```astro
---
// src/pages/posts/[id].astro
export async function getStaticPaths() {
  const response = await fetch('https://jsonplaceholder.typicode.com/posts');
  const posts = await response.json();

  return posts.map((post) => {
    return {
      params: { id: post.id.toString() },
      props: { post }, // Pass the post data directly!
    };
  });
}

// Access the props passed from getStaticPaths
const { post } = Astro.props;
---

<article>
  <h1>{post.title}</h1>
  <p>{post.body}</p>
</article>
```

By passing the data via `props`, you avoid having to fetch the same data twice (once for the route generation, and once for the page content).

## GraphQL and Headless CMS

Astro is completely agnostic when it comes to data sources. You can use any Headless CMS (Contentful, Sanity, Strapi, WordPress) or GraphQL endpoint.

Fetching GraphQL is just an HTTP POST request:

```astro
---
const query = `
  {
    allPosts {
      title
      slug
    }
  }
`;

const response = await fetch('https://my-graphql-endpoint.com', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ query }),
});

const json = await response.json();
const posts = json.data.allPosts;
---
```

## Summary

- Astro provides a global `fetch()` function that runs at build time.
- You can securely use API keys in the frontmatter because the code is stripped from the client.
- Top-level `await` is fully supported in Astro components.
- For dynamic routes, fetch your data inside `getStaticPaths()` and pass it via `props`.
