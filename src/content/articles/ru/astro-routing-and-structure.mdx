Любое знакомство с новым фреймворком начинается с понимания того, как в нём всё устроено на уровне файлов и как создаются новые страницы. В этом уроке мы подробно разберем структуру проекта Astro и его мощную систему маршрутизации.

## Стандартная структура папок

Когда вы инициализируете новый проект Astro, вы получаете примерно следующую структуру:

```text
├── public/
├── src/
│   ├── components/
│   ├── layouts/
│   ├── pages/
│   └── styles/
├── astro.config.mjs
├── package.json
└── tsconfig.json
```

Давайте разберем основные директории:

1. **`public/`** — папка для статических ассетов, которые не нужно обрабатывать при сборке (шрифты, favicon, изображения, `robots.txt`). Всё, что лежит здесь, будет скопировано в финальную сборку "как есть" и будет доступно в корне вашего сайта (например, `public/logo.png` будет доступно по адресу `/logo.png`).
2. **`src/`** — исходный код вашего проекта. Именно здесь происходит вся магия.
3. **`src/pages/`** — **самая важная папка**. Каждый файл `.astro`, `.md` или `.html` в этой папке автоматически становится страницей вашего сайта.
4. **`src/components/`** — здесь хранятся ваши переиспользуемые компоненты (кнопки, карточки, шапка сайта). Они могут быть написаны на Astro, React, Vue и т.д.
5. **`src/layouts/`** — обертки для ваших страниц (шаблоны), которые задают общую структуру (например, теги `<html>`, `<head>`, `<body>`, подключение глобальных стилей).

## Файловая маршрутизация (File-based routing)

Astro использует интуитивно понятную файловую маршрутизацию. Вам не нужно писать сложные конфигурации для роутера (как это часто бывает в React Router). Файл на диске = URL на сайте.

Пример маршрутизации:
- `src/pages/index.astro` -> `yoursite.com/` (Главная страница)
- `src/pages/about.astro` -> `yoursite.com/about`
- `src/pages/blog/index.astro` -> `yoursite.com/blog/`
- `src/pages/blog/post-1.md` -> `yoursite.com/blog/post-1`

Как видите, Astro автоматически понимает вложенность папок и поддерживает не только `.astro` файлы, но и обычный Markdown (`.md` или `.mdx`) прямо из коробки!

## Динамическая маршрутизация

Что делать, если у вас 1000 статей в блоге? Вы же не будете создавать 1000 файлов `.astro` вручную! 
Для таких случаев используются **динамические маршруты**.

В Astro динамический параметр в URL обозначается квадратными скобками `[ ]` в названии файла.

Например, файл `src/pages/blog/[slug].astro` сможет обработать запросы вроде:
- `/blog/hello-world` (в этом случае параметр `slug` будет равен `hello-world`)
- `/blog/astro-is-awesome` (`slug` = `astro-is-awesome`)

### Catch-all маршруты (Ловля всего)

Иногда вам нужно, чтобы один файл обрабатывал сразу несколько уровней вложенности. Для этого используется синтаксис `[...param].astro` (три точки).

Например, файл `src/pages/docs/[...path].astro` перехватит:
- `/docs/setup`
- `/docs/architecture/islands`
- `/docs/api/v1/endpoints`

Это невероятно полезно для создания сложной документации или вложенных категорий.

## Функция `getStaticPaths()` — Генерация статики

Astro по умолчанию является статическим генератором сайтов (SSG). Это значит, что все страницы должны быть сгенерированы в момент выполнения команды `npm run build`.

Если вы используете динамический маршрут (например, `[slug].astro`), Astro должен **заранее знать**, какие именно значения `slug` существуют, чтобы сгенерировать HTML файлы для каждого из них.

Для этого внутри динамического маршрута вы обязаны экспортировать функцию `getStaticPaths()`:

```astro
---
// src/pages/blog/[slug].astro

export async function getStaticPaths() {
  // Возвращаем массив всех возможных путей
  return [
    { params: { slug: 'hello-world' } },
    { params: { slug: 'astro-is-awesome' } },
    { params: { slug: 'my-third-post' } }
  ];
}

const { slug } = Astro.params;
---

<h1>Пост: {slug}</h1>
```

Во время сборки Astro вызовет эту функцию, увидит массив из 3 элементов и сгенерирует 3 статических HTML файла. 

На практике вы редко будете хардкодить этот массив. Обычно вы будете запрашивать список путей из API, базы данных или ваших локальных Markdown файлов (об этом мы поговорим в уроке про Content Collections!).
